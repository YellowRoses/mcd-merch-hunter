# mcd-merch-hunter · 麦麦周边猎人

> **别为了一个周边，多花一顿饭钱。**

一个基于麦当劳 MCP 的开源 Skill：针对想收藏麦当劳周边的用户，自动追踪限量周边发售规则，穷举「最低价餐品 + 加价购 + 优惠券 + 积分兑换」组合，算出**周边净到手成本**最低的方案。

---

## 💰 先看效果

想拿一顶麦当劳 × PEACEMINUSONE（G-DRAGON）联名复古棒球帽，官方规则是「任意餐品消费加 39.9 元即可得」。

| 路径 | 组合 | 实付 |
|---|---|---|
| ❌ 常见误区 | 精选单人餐三件套 ¥34.5 + 帽子 ¥39.9 | **¥74.4** |
| ⚠️ 次优 | 精选超值随心配 ¥13.9 + 帽子 ¥39.9 | ¥53.8 |
| ✅ 本 Skill 推荐 | 圆筒冰淇淋 ¥5.0 + 帽子 ¥34.9（随单购） | **¥39.9** |

如果想把三期周边（棒球帽 + 联名徽章 + 限定丝巾）集齐：

| 方案 | 三期总支出 |
|---|---|
| 不优化 | (¥34.5 + ¥39.9) × 3 = **¥223.2** |
| 本 Skill 优化 | (¥5.0 + ¥34.9) × 3 = **¥113.7** |

**同一个东西，最多差 ¥109.5。**

> 数据来自 2026-10-13 对麦当劳 MCP 的真实接口调用。实际价格、供应状态以麦当劳官方渠道实时结果为准。

## 🎯 目标用户

- **周边收藏党**：想要联名帽子、徽章、丝巾、开心乐园餐玩具，但不想花冤枉钱的人
- **凑齐全套党**：面对 6～10 款随机发放的玩具系列，想算清「集齐要花多少钱」的人
- **积分待过期党**：账户里躺着一批即将过期的麦当劳积分，想换成实物而不是白白浪费的人

## ✨ 核心能力

| 能力 | 说明 |
|---|---|
| 🔍 **周边识别** | 从门店菜单中直接识别周边商品——实测发现周边本身就是菜单里的可定价实体 |
| 🧮 **最低成本组合** | 同时给出激进（绝对最低价锚点）与保守（排除酱料配料）两套方案 |
| 🎟️ **四路券池合并** | 麦麦省可领券 + 一键领取后新增 + 账户已有 + 门店专属，少查一路就少省钱 |
| 💳 **隐藏优惠挖掘** | 自动发现周边本身的随单购差价（实测一顶帽子差 ¥5） |
| ⏰ **抢购时间窗** | 区分「APP 积分抢先购」与「正式开售」，提前 5 分钟提醒 |
| 📊 **净到手成本** | 扣掉餐食刚需价值，告诉你为这个周边真正多掏了多少 |

### 核心公式

```
周边净到手成本 = 实付现金 + 消耗积分折算金额 − 餐食刚需价值
```

净成本为负 = 这顿饭比日常还便宜，**相当于白得一个周边**。

## 🚀 快速开始

### 方式一：离线跑通（无需 MCP Token）

内置脱敏样例数据，克隆即可复现完整优化流程：

```bash
git clone https://github.com/YellowRoses/mcd-merch-hunter.git
cd mcd-merch-hunter

python optimizer.py                # 输出激进/保守两套方案对比
python scripts/selftest.py         # 24 项断言
```

预期输出：

```
### 目标周边：麦当劳联名复古棒球帽
官方定价 ¥39.9 元（随单购价 ¥34.9 元，省 ¥5.0）

| 排名 | 方案 | 实付现金 | 净到手成本 | 说明 |
|---:|---|---:|---:|---|
| 1 | 麦当劳联名复古棒球帽 | ¥34.90 | ¥4.90 | 随单购直购 |
| 2 | 圆筒冰淇淋(5.0) + 麦当劳联名复古棒球帽 | ¥39.90 | ¥9.90 | 锚点餐品 + 随单购 |
| 3 | 灰焰圆筒(5.0) + 麦当劳联名复古棒球帽 | ¥39.90 | ¥9.90 | 锚点餐品 + 随单购 |
```

### 方式二：接入真实麦当劳 MCP

1. 到 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) 手机号登录，控制台激活领取 MCP Token（免费）
2. 复制配置模板并填入 Token：

```bash
cp mcp-config.example.json .mcp.json
# 将 ${MCD_MCP_TOKEN} 替换为你的真实 Token
```

3. 在任意支持 MCP 的客户端（Claude Code / Cursor / Cherry Studio / Trae / WorkBuddy）中加载 `SKILL.md`
4. 直接说：

> 「我想拿 GD 联名那个棒球帽，怎么买最便宜？」

## 🧠 技术架构

```
┌─────────────┐     ┌──────────────────┐     ┌──────────────┐
│  麦当劳 MCP  │────▶│   optimizer.py   │────▶│    Agent     │
│  实时取数    │     │  确定性组合优化   │     │  讲解与确认   │
└─────────────┘     └──────────────────┘     └──────────────┘
```

**分工原则：取数交给 MCP，算术交给代码，表达交给 Agent。**

为什么不让大模型算价格：周边获取是典型组合决策——菜单几十项、券十几张、每张券规则不同，还要判断「为凑满减而加购是否划算」。多步算术 + 约束推理正是大模型错误率最高的场景，而价格错一位数就是事故。因此 `optimizer.py` 做成**纯标准库、零依赖**的确定性计算：同一输入永远得到同一输出。

一条保守但重要的规则：**方案价 ≤ 用户实付价**。拿不准的优惠宁可不报，也绝不给用户一个"到店付不出来"的假低价。所有价格最终以 `calculate-price` 实算为准。
